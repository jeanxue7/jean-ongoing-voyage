## 可移交的文件结构

当前已建立 `docs/`、`assets-originals/` 与 README。进入设计开发后按需要增加：

```text
design/                 人物样张、逐场景 UI、设计说明与生成提示词
public/assets/          已选定可上线的压缩图片和动画素材
src/components/         场景、人物、导航、相册等独立组件
src/content/            个人信息、文章、酒款、山峰、旅行记录
src/pages/ 或 app/      采用何种目录取决于最终框架
docs/decisions.md       用户确认的设计决定
docs/changelog.md       完成内容、验证结果、待办项
```

框架与依赖在 UI 需求明确后选择。内容和视图分离，普通文字优先 Markdown，结构化记录使用 JSON/TypeScript；保存依赖锁文件和准确的安装、启动、构建命令。网站应能在本地独立运行和编辑。

生成的图片只能保证像素编辑，不能假定含可编辑图层。若采用插画分层动画，要分别保存背景、前景、人物与可点击物件；若采用真 3D，另存模型、贴图、动作文件和源工程。

## 最小功能拆分初稿

这是一份后续细化的起点，不表示界面已确定。

| 功能 | 最小行为与验收点 |
| --- | --- |
| 开始探索 | 点击后进入第一场景；无动画模式也能访问内容 |
| 场景推进 | 滚动切换进度；人物随之移动；停止输入后停步 |
| 直接导航 | 直接到指定栏目；当前栏目可识别；手机可操作 |
| 场景入口 | 有可读名称；点击/键盘都能打开内容；不会只靠悬停发现 |
| 写作分类 | 可切换三类；没有内容时不显示虚构文章 |
| 文章详情 | 标题、正文或摘要、原文链接；返回恢复原位置 |
| 播客 | 展示介绍与实际收听链接；站内音频作为后续可选项 |
| 酒款详情 | 图、名称、推荐理由；缺失字段不显示无意义占位 |
| 空间相册 | 开图、上一张、下一张、关闭；键盘和触屏可操作 |
| 小程序入口 | 展示真实二维码与打开说明；有有效链接时再适配跳转 |
| 关于我 | 用户确认的简介与经历；无虚构履历 |
| 山峰选择 | 点击山峰打开对应故事和照片；没有照片时展示文字状态 |
| 旅行地图 | 点击地点查看内容；同时提供地点列表；同一记录可关联文章 |
| 公益故事 | 展示真实项目经历、照片与说明 |
| 联系 | 邮箱或社交入口可用；复制操作有成功/失败反馈 |
| 动画降级 | 减少动态效果时无强制视差，所有入口仍可用 |
| 加载与失败 | 图片延迟加载时保持布局；失败有可读提示和替代文本 |

## GitHub 与本地备份

本地完整保存文档、源码、设计文件与原始素材。GitHub 用于文档、源码与适当体积的已选素材版本备份。原图批量资料默认留在本地 `assets-originals/`，避免把整个原图目录直接公开或误当作已上线内容。

远端仓库尚未指定时，不声称已上传。用户提供现有仓库地址或明确新仓库归属后，连接远端并同步；建议个人开发备份使用私有仓库。上线部署与代码备份分开处理。

每个阶段形成一个可回退版本：框架、视觉确认、可运行原型、首版内容完成。交接时注明当前阶段、入口文件、运行命令、已验证行为和剩余任务。
